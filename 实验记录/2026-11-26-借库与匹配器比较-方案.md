# 借库与匹配器比较：实验方案

2026-11-26 · 状态：方案，待跑

## 要回答的两个问题

1. 借哪个库：全唐文 995ejelvk0、史記 988g3f0wsu、殿本 96mid1ogzk，还是合借。
2. 5a 用哪种匹配：生产的 HOG 粗排加弹性覆盖分，还是 CNN 相似度（`glyph_match.sim_model`），或者两者平均（`fuse: mean`）。

## 查询集（本书的金标）

本书字库是空的，没有人裁格，所以分两层：

- **大样本，参校本对位当标签**：1c 试跑页切出的字格，取和参校本对位稳的格，用参校本的字当标签，约 2–3 千格。参校本约 98%，标签有约 2% 噪声，但所有方案面对的噪声相同，可以用来排序。
- **小样本，人审金标**：首批人审约 200 格，用来核对大样本的结论，并专门量「放行里错」。

## 比较矩阵

库（都用 `scope: human+auto`，人裁加看图确认的自动刻例）：全唐文、史記、殿本、全唐文加史記。

匹配器：

| 记号 | 说明 |
|---|---|
| prod | HOG kNN 粗排加弹性对齐 cov（现在缺省） |
| cnn_base | 通用相似度模型 glyph_sim_base_v1（殿本、史記、全唐文合训） |
| cnn_qtw | 全唐文专训 glyph_sim_qtw_v2 |
| cnn_shiji | 史記专训 glyph_sim_shiji |
| fuse | 上面某个 CNN 和 cov 取平均（`fuse: mean`） |

注意偏差：专训模型在自己那本书的库上可能占便宜。公平比较库要用 cnn_base 和 prod；专训模型只作参考。

## 指标

- 覆盖：标签字在借来的库里有刻例的格占比。
- 首位对：有刻例的格里，库首位就是标签字的比例（己已巳、日曰折叠）。
- 证人放行：按生产门槛判 same 的格占比，即借库能省下多少人审。
- 放行里错：判 same 但字不对的比例。这是硬指标，要不超过 0.5%。
- 每对耗时。

## 判法

先卡「放行里错 ≤ 0.5%」，再比「证人放行」，取最高的库和匹配器。然后把选定的配置写进 workspace.yaml，在 1c 试跑页上和「不借库」对比 pending-stats，看人审率实际降多少。

## 工具
